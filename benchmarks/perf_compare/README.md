# perf_compare

Times every implementation of every CGO kernel over a size sweep on Saturn
(Spike or FireSim), with 100 warm-up and 1000 timed iterations per
(kernel, implementation, size) via `rdcycle`/`rdinstret`, each output checked
against the XNNPACK kernel:

| Lane | Source |
|---|---|
| Upstream | XNNPACK's RVV microkernel (`XNNPACK_SRC`, XNNPACK at `3ed73f57`) |
| Sol | the SALTy-rn translation (`sols/cgo-kernels`) |
| Autocomp | the search's best candidate (`output/<run>/best_candidate_so_far.txt`) |
| Neon2RVV | XNNPACK's Neon kernel through `src/neon2rvv.h` |
| Autovec | XNNPACK's scalar C through GCC's auto-vectorizer |

```bash
python3 scripts/gen_perf_compare.py                  # writes benchmarks/perf_compare/src/main.c
west build -p -b spike_riscv64 benchmarks/perf_compare
spike --isa=rv64gcv_zvfh_zvl512b build/zephyr/zephyr.elf   # or run the same ELF on FireSim
```

Which sections run is set by the `RUN_*` defines the generator writes at the
top of `main.c`. Results print as a table and as `CSV:` lines
(kernel, impl, batch, total_cycles, total_instrs, cycles/elem, instrs/elem).

## Provenance

The original app (`zephyr-chipyard-sw/samples/kernel_bench`, generated by the same script under its
old name `gen_kernel_bench.py`) is no longer available; this one is rebuilt:

- `src/neon2rvv.h`: neon2rvv (https://github.com/howjmay/neon2rvv) at
  `2abbe36` (2026-04-25), the last commit before the June 2026 results. It
  leaves exactly the zip intrinsics the generator supplies itself
  (`vzip1q_f32`, `vzip2q_f32`, `vzip1_u32`, `vzip2_u32`) commented out, as the
  generator expects. Apache-2.0, see `src/NEON2RVV_LICENSE`.
- `prj.conf`: Autocomp's `rvv_bench` configuration, plus floating-point printf.
- `riscv_vector.conf`: V and Zvfh.
- `src/main.c`: the generated benchmark, committed so it builds without the search outputs;
  regenerate it with `scripts/gen_perf_compare.py`.
- `CMakeLists.txt`: written for this app. Compiler flags may differ from the
  original's; reproduced cycle counts can therefore differ from the June 2026
  `kernel_bench_results.csv`.

The generated `main.c`, with every section enabled, compiles with GCC
(`-march=rv64gcv_zvfh -O3`) against this header; it has not yet been built
with Zephyr or run.
